Long-Term Memory Access in Small Language Models

A comparative study of memory-augmented architectures for multi-session dialogue: BM25 sparse retrieval vs. dense vector retrieval, evaluated on Gemma 3 4B across two large-scale benchmarks.

Research Question

Does augmenting a 4-bit quantized Gemma 3 4B SLM with long-term memory — either BM25 sparse retrieval or dense vector retrieval — significantly improve multi-session question-answering performance compared to a memoryless baseline?

Condition key:
Baseline (No Memory)
BM25 (Sparse)
Vector (Dense)
Baseline · No Memory

Stateless Condition

The model answers each query with only the current-turn context — no access to prior conversation history. Serves as the control.

  • No memory store; no retrieval step
  • Zero retrieval latency
  • Minimal token overhead (~0.02%)
  • Cannot answer cross-session queries
BM25 · Sparse Retrieval

Keyword-Based Memory

SQLite FTS5 inverted index with BM25 scoring, Gemma 3 4B query expansion, and recency-weighted hybrid re-ranking.

  • SQLite FTS5 inverted index
  • Query expansion: exactly 4 keyword variants
  • Recency decay: λ = 0.1 day⁻¹ (t½ ≈ 7 days)
  • Hybrid reranking: α = 0.3 (BM25 + cosine)
Vector · Dense Retrieval

Semantic Memory

EmbeddingGemma 300M generates 768-dimensional embeddings stored in FAISS IndexFlatL2, retrieved by L2 proximity.

  • EmbeddingGemma 300M — 768-d vectors
  • Mean-pooling + L2 normalization
  • FAISS IndexFlatL2 nearest-neighbor search
  • Top-K = 5 memories retrieved per query

Summary of Findings

Vector achieves best overall performance

Highest answer relevance, highest Recall@5, and lowest memory error rate on both benchmarks. All effect sizes are very large (η² = 0.31–0.70).

BM25 retrieves well but disrupts generation quality

BM25 Recall@5 is statistically equivalent to vector — yet answer relevance falls well below the no-memory baseline (LME: 1.0 vs 3.49; LoCoMo: 1.81 vs 3.82).

Baseline outperforms BM25 on answer quality

Paradoxically, the memoryless condition produces better-quality answers than BM25, suggesting keyword-injected context can be harmful if not semantically matched.

All differences are statistically significant

Repeated-measures ANOVA (GG corrected) confirms p < 0.001 for all five metrics on both benchmarks. The only non-significant comparison is BM25 vs Vector on Recall@5.

Evaluation Benchmarks

LongMemEval

LongMemEval (LME)

Evaluates long-term memory in assistant-style single-session conversations. Each question requires cross-turn recall. LTM is reset per question_id.

500 questions Single long-session format 5 question categories
Categories: Single-Hop · Multi-Hop · Temporal Reasoning · Knowledge Update · Abstention
LoCoMo

LoCoMo v1.0

Long-context multi-session conversations modeled on personal assistant dialogues. LTM is shared across all QA pairs in one conversation block; reset per conversation sample.

1,861 questions Multi-session format 3 question categories
Categories: Single-Hop · Multi-Hop · Temporal Reasoning
Stage 2 — LLM-as-Judge (Gemini 2.5 Flash)
Faithfulness (1–5) · All items
Is the response fully grounded in retrieved context with no hallucinated claims? Score 5 = every claim supported, 1 = contradicts context.
Answer Relevance (1–5) · All items
Does the response directly and completely answer the question? Score 5 = fully answers, 1 = off-topic or unjustified refusal.
Abstention Accuracy (1–5) · Abstention items only
Does the model correctly express uncertainty when the answer is absent from memory? Score 5 = clearly states it doesn't know.
Scoring scope: All collected responses submitted to Gemini 2.5 Flash. Evaluation runs in parallel across up to 8 concurrent API workers with checkpoint saves every 50 items.

Statistical Conclusions

H1 Supported: Vector memory significantly improves answer quality

Vector significantly outperforms baseline on answer relevance (LME: d = −0.78; LoCoMo: d = −0.23) and reduces memory error rate to ~4% from 15–75% baseline. All p < 0.001.

H2 Partially Rejected: BM25 retrieves but degrades generation quality

BM25 Recall@5 ≈ vector Recall@5 (difference not significant), yet BM25 answer relevance is dramatically lower than both baseline and vector. Retrieval quantity does not guarantee generation quality.

Very Large Effect Sizes Across All 10 Metric × Dataset Combinations

Partial η² ranges from 0.307 to 0.997. Every result far exceeds the conventional "large" threshold (η² = 0.14), confirming both statistical and strong practical significance.

Only Non-Significant Comparison: BM25 vs Vector on Recall@5

LME: p = 0.083, d = −0.040 (ns). LoCoMo: p = 0.613, d = −0.031 (ns). Both memory systems retrieve at statistically equivalent rates; performance separation is driven by generation quality, not retrieval quantity.
